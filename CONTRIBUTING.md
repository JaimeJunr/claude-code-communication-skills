# Contributing

## Add or change an upstream skill

1. Edit [stack.json](stack.json): add an allowlisted `copy` entry or a source
   with `id`, `repo`, `ref`, `license`, `author`, `plugin`, `description`,
   `category`, and non-empty `license_files`. Every current source tracks main.
2. Run `python scripts/sync.py`, or use `--src` with clean existing clones
   named `<owner>_<repo>`. Local mode reads HEAD, makes no fetches, and fails
   if a clone is missing.
3. Update the routing table in
   `plugins/communication-stack/skills/communication-stack/SKILL.md`.
4. Add a conflict ruling when required and consult the full register in
   [DESIGN.md](docs/research/DESIGN.md).
5. Review changed licenses/notices, source helper files, and the three owned
   adapters. Run the behavioral evaluation TODO before releasing an update.

Never edit a generated upstream plugin by hand; sync overwrites it. Put reviewed
changes in `stack.json` `patches` with a `why`, reviewed `upstream_commit`,
and relevant `conflicts`. A file patch can combine:

- `description`: replace a single-line or folded/literal block description,
  preserving other frontmatter.
- `drop_keys`: remove top-level scalar frontmatter keys.
- `frontmatter`: set top-level scalar keys.
- `model_invocable: true`: remove an upstream invocation restriction if present.
- `replace`: `[{ "pattern": <regex>, "with": <replacement>, "count": 1 }]`
  applied to the body only. A missing match or changed expected count fails
  before publishing that source's replacement plugin.

The sync tool uses only the Python standard library. Source files are copied
before patches; the lock records their raw SHA-256 hashes and full commits.
Inspect raw bodies at those commits instead of maintaining a duplicate vendor
tree. Review notice/license changes as changes to the grant, not just prose.

Use `reference_only: true` for a source contributing resources to an owned
plugin. Its `copy[].to` paths stay under its `license_dir`; sync overlays those
resources and preserves the local manifest, router, and styles. This is how
talk-normal stays inside the plugin using it, without registering an installer.

A copy entry may set `plugin` to an owned plugin for a reference-only destination
under `skills/<plugin>/references/upstream/<source-id>/`. Caveman and ADHD use
this for adapter license/notice copies so the four-style plugin can be installed
independently. These files are also generated; keep them byte-identical to source.

A source belongs here when it is maintained, permissively licensed, adds a
distinct task, and can be reconciled through small patches. If changes demand a
divergent fork, reconsider inclusion.

## Change the router or output styles

`plugins/communication-stack/` is hand-written except the explicitly managed
upstream reference directories. The router chooses one task recipe and holds
the chat/prose/machine precedence ladder. All six upstream leaf skills remain
model-invocable. Their narrow descriptions allow loading only on explicit
request or when the communication-stack router selects them.

The router invokes exactly one chosen namespaced skill through the Skill tool.
Never invoke more than one editor per task. If its plugin is not installed,
report that and give `/plugin install <name>@communication-stack`.

Keep exactly four optional styles. Every style needs `name`, `description`,
`keep-coding-instructions: true`, and `force-for-plugin: false`. Preserve the
ELI5 style exactly as fixed in DESIGN.md section B. Other adapters carry a short
provenance comment and preserve their upstream grants. Do not add hooks or
modify user settings during sync.

`scripts/token_budget.py` uses tiktoken `o200k_base`: 8,000 tokens per local
SKILL.md, 20,000 per agent if any are added, and 2,000 per output style.
References are loaded only when needed and excluded from these entrypoint caps.
Empty scans fail.

## Before opening a PR

Use tests first for contract/tooling changes: observe the relevant failure,
implement, then run the repo's light suite. Do not run sibling tests.

```bash
python -m venv .cache/venv
source .cache/venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
python scripts/sync.py --check
python scripts/token_budget.py
claude plugin validate .
for p in plugins/*/; do claude plugin validate "$p"; done
```

Report the number of files/sources/recipes actually scanned, and whether any scan
was empty. Verify a repeated local sync preserves the generated bytes and owned
files. Packaging tests do not establish response quality or token savings;
complete the [evaluation plan](docs/research/DESIGN.md#e-biggest-risk-and-cheap-evaluation)
before claiming those results.
